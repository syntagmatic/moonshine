# Claims: Parallel Coordinates series

This series has not had a full fact-check. The entries below are only the leads
flagged in `plans/FACT-CHECK.md`, settled on 2026-09-27: each was checked by
derivation, by reading or rerunning the figure code, or against a named source,
and the page was fixed or left as written.

| Page | Claim | Verdict | Source or derivation | Fix |
|---|---|---|---|---|
| 02 | Crossings "gather where many pairs share a linear trend" | wrong, fixed | Convergence point sits at x = 1/(1-m); only m < 0 puts it between the axes, as the page itself says earlier. A positive trend puts it outside the strip. | Sentence now says crossings gather between the axes for a negative trend, move outside the strip for a positive one, and scatter with none. |
| 03 | "With equal coefficients the polylines form a symmetric fan" | wrong, fixed | Reran the Fig 1 sampler (seed 42, a = 1,1,1, c = 5): adjacent-pair correlations are -0.38 (x1,x2) and -0.49 (x2,x3), so both gaps show a loose X, and the sampling is not symmetric in the three variables. The large-coefficient pinch claim holds (rejection sampling on the box forces the dominant variable into a narrow range). | Replaced with "the segments cross in a loose X between each pair of axes, because on the plane raising one coordinate pushes the others down." |
| 03 / index / PROMPT | Hyperplanes show "a signature of indexed points" | wrong, fixed | The Hyperplanes section only draws sampled polylines; no indexed-point construction for hyperplanes appears anywhere in the series. | Index intro now says "hyperplanes as constrained families of polylines"; PROMPT now says a hyperplane "constrains its points' polylines into a structured family". |
| 04 | Greedy ordering "is the nearest-neighbor heuristic for the TSP" | wrong, fixed | `greedyCorrelationOrder` starts from the best pair and extends whichever end gives the higher |r|; classic nearest neighbour extends one end only. | Now "a variant of the nearest-neighbor heuristic ... that grows the chain from both ends instead of one". |
| 04 | Of 360 orderings, "most of them hide the interesting structure" | unverifiable, cut | No count of informative vs uninformative orderings exists on the page or in a source. 6!/2 = 360 is correct. | Now "360 distinct orderings, too many to inspect one by one." |
| 05 | Waist is "to the right of the right axis for positive correlation" | wrong, fixed | Band half-width at position t is proportional to sqrt(w'Σw), w = (1-t, t); minimiser t* = (σx² - rσxσy)/(σx² + σy² - 2rσxσy). For a thin cluster along y = mx this is 1/(1-m): right of the right axis only for 0 < m < 1, left of the left axis for m > 1. Fig 2 uses equal spreads (ellipse at 45°), where t* = 1/2 for every r and a positive cluster's segments run near parallel. | Waist position now tied to the trend slope with all three cases, citing article 1, plus a sentence on Fig 2's equal spreads. r = 1 sentence now says the cluster lies on a line. |
| 05 / 06 | Spelling "h-star" (05) vs "hstar" (06, index) | inconsistent, fixed | 06 and the index card use "hstar". | 05 now uses "hstar" in both places. |
| 06 | Circle's bowtie "widest at the height of the center and pinching toward the extremes" | wrong, fixed | For a circle of radius r at c, the band at t is (1-t)c1 + t c2 ± r sqrt((1-t)² + t²): narrowest at t = 1/2 (full width diameter/sqrt 2), widening toward and past each axis. Matches `computeHstarEnvelope`. | Now "a bowtie level with the circle's center, narrowest midway between the axes, where its width is the diameter divided by sqrt 2, and widening toward each axis and past it." |
| 06 | Ellipse bowtie "wider on one side", "rotation tilts the whole envelope", ellipse "makes the bowtie asymmetric" | partly wrong, fixed | Width on each axis is the ellipse's extent along that variable; waist t* = (M11 - M12)/(M11 + M22 - 2M12) slides toward the narrower axis. At 45° rotation M11 = M22 so the bowtie is symmetric again. The center line stays level (ellipse centered at (5,5)), so nothing tilts. | Both sentences rewritten to say this. |
| 07 | Angular brush selects "by the ratio between variables", a wedge, with formula slope = (x_j - x_i)/d in [s1, s2] | wrong, fixed | A slope range is a diagonal band of differences, not a wedge. The figure actually tests segment-segment intersection: each strum point is a Cartesian line, all through the point dual to the strum's line, so one strum selects a double wedge at that apex; two strums select points crossing exactly one (XOR). | Formula replaced with the product-of-two-lines condition; prose, intro line, heading, caption, aria label and PROMPT now describe wedges through an apex. Status-bar text ("a second strum defines a wedge") left as UI copy. |
| 08 | Fig 1 hint: labels turn red "outside the normal bundle" vs caption "exceeds spec" | wrong, fixed | Code tests `current < specLo || current > specHi`; spec limits are ±3σ (outlet temp ±3.1σ). | Hint now says "when the value passes a spec limit". |
| 08 | Reactor data not captioned as simulated until Fig 2 text | fixed | PROMPT rule: invented data is captioned as simulated. Data is generated in-page from normals. | Fig 1 caption now says "on simulated sensor data". |
| 09 | "A controller can't evaluate the CPA formula for every pair" | wrong, fixed | Ground-based safety nets such as EUROCONTROL's Short Term Conflict Alert compute predicted separation (CPA) for all track pairs continuously. | Now says conflict-detection software already does this, and PC adds context on what the flagged pairs share. |
| 10 | 3-link solution family is "the null space of the redundant arm"; N - K in general | imprecise, fixed | The family is the self-motion manifold; the Jacobian's null space is its tangent at each solution. Dimension N - K holds away from singular configurations. | Paragraph and Fig 4 caption now say "self-motion", mention the Jacobian's null space, and add "away from singular configurations". |
| 11 | "The slopes between axes show trade-off rates" | wrong, fixed | A segment's slope compares one design's two normalised scores; a trade-off is a relation across designs.
