The Mapper Algorithm

Part 3 of 3. A different philosophy: instead of computing exact homology, Mapper produces a combinatorial graph that summarises the shape of data. Choose a lens, cover the range, cluster the preimages, build the nerve.

Persistent homology gives us Betti numbers and barcodes, precise algebraic invariants. But sometimes what we want is not a number but a picture: a low-dimensional graph that summarises how the data is connected. The Mapper algorithm (Singh, Memoli, Carlsson, 2007) produces exactly this.

The pipeline

Mapper has four steps:

  1. Lens function. Choose a function f : X → ℝ (the "lens" or "filter") that captures some aspect of the data. Common choices: a coordinate, distance from a centroid, eccentricity, density.
  2. Cover. Partition the range of f into overlapping intervals. The overlap is essential; it is what creates edges in the output graph.
  3. Cluster. For each interval, pull back the points in its preimage and cluster them (single-linkage, DBSCAN, or any clustering method). Each cluster becomes a node in the output.
  4. Build the nerve. Two nodes are connected by an edge if the corresponding clusters share a data point (possible because intervals overlap). The resulting graph is the Mapper output.

Mapper is a topological lens on data. It does not compute homology; it produces a graph. But the graph preserves topological features: a loop in the data becomes a cycle in the Mapper graph; a branching structure becomes a branching graph. The choice of lens determines which features are revealed.

What the Mapper graph reveals

For the circle preset with the x-coordinate lens, Mapper produces a cyclic graph: the loop in the data is captured as a cycle in the graph. For the figure-8, a branching graph appears. For clusters, the graph shows disconnected components.

The number of intervals controls resolution: more intervals produce a more detailed graph (but also more noise). The overlap percentage controls connectivity: higher overlap creates more edges (adjacent intervals share more points).

Mapper vs persistent homology

Persistent homology and Mapper answer different questions:

  • Persistent homology gives algebraic invariants (Betti numbers, barcodes) that are provably stable and parameter-free once the filtration is chosen. It answers: "how many holes does the data have?"
  • Mapper gives a combinatorial summary (a graph) that depends on several choices (lens, cover, clustering). It answers: "what does the shape of the data look like?"

Mapper is more exploratory; persistent homology is more rigorous. In practice, they are often used together: persistent homology to establish that the data has interesting topology, and Mapper to visualise what that topology looks like.

Mapper is TDA's exploratory tool. Where persistent homology provides rigorous invariants, Mapper provides visual intuition. The two are complementary: use persistence to establish that topology exists, and Mapper to see what it looks like.

What we take with us

  • Mapper pipeline: lens → cover → cluster → nerve.
  • The output is a graph that summarises the shape of the data.
  • The choice of lens, intervals, and overlap affects the output. Mapper is exploratory, not canonical.
  • Mapper and persistent homology are complementary: one gives invariants, the other gives pictures.
