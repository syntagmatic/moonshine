Core Concept

A tensor network diagram is a bookkeeping device for multilinear algebra. A node represents a tensor. Each wire incident to that node represents one index of the tensor. When a wire connects two tensor nodes, the corresponding index is summed over. When a wire is left open, that index survives in the output.

For a matrix product, the usual expression draws as two nodes joined by one wire. For a larger expression, the same rule scales up: connected wires are internal indices and open wires are external indices. This is close in spirit to Penrose graphical notation, but tensor-network papers often emphasize computational structure as much as algebraic type.

The diagram is not the tensor entries themselves. It is a pattern of factorization. Instead of storing one dense array with many indices, one stores smaller tensors whose shared indices mediate the dependence among pieces. The size of a shared index is often called its bond dimension. Increasing a bond dimension can make the representation more expressive, but it usually increases storage and contraction cost.

Contraction Order and Cost

The order of contractions does not change the exact mathematical result, assuming exact arithmetic and compatible dimensions. It can change the intermediate arrays dramatically. In the example, contracting the two columns first creates intermediates of size 720. Contracting the two rows first creates intermediates of size 1500. Multiplying non-neighboring tensors first creates an intermediate with 1,080,000 entries before any summation has happened.

This sensitivity is one reason tensor networks are both useful and delicate. They can make a high-dimensional object tractable when the network geometry and bond dimensions are favorable. But the diagram does not automatically come with a cheap evaluation strategy. Finding a good contraction sequence is a separate problem.

For general networks, optimal contraction order is tied to graph structure. Markov and Shi related tensor-network simulation cost to treewidth in the study of quantum-circuit simulation. Modern tensor software often searches for an exact path only for small networks, then uses branch-and-bound, dynamic programming on restricted cases, random-greedy methods, or other heuristics for larger ones. A low-cost path is therefore a mathematical and algorithmic feature of the network, not just an implementation detail.

Network Families

Several named tensor network families are best understood as repeated diagram shapes. The list below is not complete, but it covers the forms most likely to appear near this notation.

Matrix Product States

A matrix product state, or MPS, arranges tensors in a one-dimensional chain. Each site has a physical index and neighboring sites share bond indices. A common open-boundary form is

MPS notation is closely connected with one-dimensional density-matrix renormalization group methods. Its chain geometry is friendly to sequential contraction, and many algorithms exploit canonical forms that make local updates stable.

Projected Entangled Pair States

A projected entangled pair state, or PEPS, extends the idea to two-dimensional and higher-dimensional lattices. A site tensor is connected to neighboring site tensors by virtual bonds and has one or more physical legs. PEPS can represent area-law patterns naturally, but contracting a general two-dimensional PEPS exactly is much harder than contracting a one-dimensional MPS. Practical calculations often use approximate boundary methods or controlled truncations.

Tree Tensor Networks and MERA

A tree tensor network has no loops. This makes many contractions straightforward, although the tree may impose its own approximation bias. MERA, the multiscale entanglement renormalization ansatz, uses a layered causal structure with disentanglers and isometries. Its diagram is built so that many local observables can be evaluated through a narrow causal cone rather than through the whole network.

Concept Summary

  • Nodes are tensors: The number of incident wires gives the number of indices, sometimes called the tensor order or rank in this context.
  • Wires are indices: A connected wire denotes a shared index to be summed. An open wire denotes an output index.
  • Bond dimensions matter: The dimension of an internal wire controls both the amount of information that can pass across that cut and the cost of contractions involving that wire.
  • Contraction order matters: Different orders give the same algebraic tensor but can create very different intermediate sizes.
  • Network shape matters: Chains, trees, grids, and layered causal networks have different contraction behavior.
  • Diagrams are computational notation: They show the algebraic expression and also expose the choices an algorithm must make to evaluate it.
