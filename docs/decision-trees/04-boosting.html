Boosting

Chapter 4 of 8. Bagging trains trees in parallel and averages them. Boosting trains trees in sequence, each one fixing the previous ensemble's mistakes. It's a completely different recipe, and on tabular data, it usually wins.

Random forests have trees vote. Boosting has trees cooperate in sequence: the first tree does its best, the second fixes its errors, the third fixes the second's misses. A chain of small specialized trees outperforms a forest of independent ones because errors are usually small structured patterns a tiny tree captures easily.

The recipe

The simplest version is five lines long. You want to predict y from features x.

  1. Start with a flat baseline prediction, the mean of all training labels.
  2. Compute residuals: each row's (true label − current prediction).
  3. Fit a small tree to predict the residuals from the features.
  4. Add a fraction of this tree's predictions to the baseline.
  5. Repeat.

The fraction in step 4 is the learning rate ν. At ν = 1.0 each tree adds at full strength; typically it's much smaller, like 0.1. Lower learning rate, more trees needed, better generalization. The rule: small learning rate, many trees, early stopping.

The growth toggle changes how the internal tree is built: level-wise grows in balanced layers; leaf-wise always expands whichever leaf would most reduce the loss, producing faster-converging but more lopsided trees. "Tree leaves" is the total number each internal tree is allowed — the total is the same under both strategies; only the shape changes.

Try setting tree leaves to 12 and learning rate to 1.0. After one tree, training is near-perfect and test error climbs with every additional tree. The overfitting pathology from chapter 2, sped up by a high learning rate. Fix: small learning rate, many iterations, stop when test error rises.

Bias, not variance

Bagging averages many high-variance, low-bias trees, killing the variance. Boosting stacks small weak learners — each captures part of the pattern — so their contributions add up into one expressive model. Bagging reduces variance; boosting reduces bias. On tabular data, boosting usually wins because real-world errors come more often from bias than variance.

Any loss function works

Everything so far used squared error. Boosting works with any differentiable loss because "residual" is the negative gradient. Log-loss for classification, Huber for robust regression, Poisson for counts. Same algorithm, different residual formula.

This generalization is Friedman's 1999 insight; before it, boosting variants looked like distinct methods.

Modern implementations

The basic algorithm is unchanged since 1999. Turning it into a production library means making it fast on a million rows, preventing quiet memorization, and handling missing values and categoricals.

Three libraries dominate, each with a different engineering focus:

XGBoost

careful

The reference. Uses second-order gradient information (curvature, not just slope) to pick splits, adds explicit regularization on leaf weights, handles missing values by learning a default routing direction, grows trees level-wise.

LightGBM

fast

Optimized for big datasets. Bins feature values into hundreds of buckets (turning split search into integer comparisons), grows trees leaf-wise, often 5–10× faster than XGBoost on large data. Default choice above a million rows.

CatBoost

rigorous

Focused on category-heavy datasets. Uses ordered boosting so earlier trees don't peek at labels through target-encoded categoricals, and oblivious (symmetric) trees for fast inference — the trick returns in chapter 8.

Picking one

Any of the three works for most problems. Try LightGBM first for fast iteration; CatBoost for category-heavy data; XGBoost for small datasets (under 100k rows) where stability matters. All three implement the same core algorithm — the difference is engineering margin and hyperparameter tuning.

Takeaways

  • Boosting is sequential. Each tree is trained to fix the previous ensemble's errors. Cannot be parallelised across trees (unlike bagging).
  • Trees are small. Depth 3–6 or so; individually weak; collectively powerful.
  • Boosting reduces bias. Where bagging reduces variance. On tabular data, boosting usually wins for this reason.
  • The learning rate is the key knob. Small learning rate + many trees nearly always beats large learning rate + few trees. Start at 0.1.
  • Any differentiable loss works. Regression, classification, counts, robust. Same algorithm, different "residual."
  • XGBoost, LightGBM, CatBoost are all boosting. The differences are engineering: second-order gradients vs histogram speed vs categorical handling.
