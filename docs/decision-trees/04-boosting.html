Boosting

Chapter 4 of 6. Bagging trains trees in parallel and averages them. Boosting trains them in sequence, each one correcting the ensemble built so far, and on tabular data it usually wins.

In a random forest the trees vote. In boosting the first tree does its best, the second fits what the first got wrong, and so on. A chain of small trees can beat a forest of independent ones because the remaining errors are often small structured patterns that a tiny tree captures easily.

The recipe

To predict y from features x, the simplest version is:

  1. Start with a flat baseline prediction, the mean of all training labels.
  2. Compute residuals: each row's (true label − current prediction).
  3. Fit a small tree to predict the residuals from the features.
  4. Add a fraction of this tree's predictions to the baseline.
  5. Repeat.

The fraction in step 4 is the learning rate ν. At ν = 1.0 each tree adds at full strength; a typical value is much smaller, around 0.1. A lower rate needs more trees and generalizes better, so the usual practice is a small learning rate, many trees, and early stopping.

The growth toggle changes how each tree is built: level-wise (XGBoost) grows balanced layers, while leaf-wise (LightGBM) always expands the leaf that most reduces the loss, which converges faster and gives more lopsided trees. "Tree leaves" caps the leaf count per tree, the same under both strategies; only the shape changes.

Try 12 leaves and a learning rate of 1.0. After one tree the training fit is near-perfect, and test error climbs with every tree after that. This is chapter 2's overfitting, sped up by the high learning rate.

Bias, not variance

Bagging averages high-variance, low-bias trees to remove variance. Boosting adds up small weak learners, each capturing part of the pattern, into one expressive model, so it reduces bias. On tabular data boosting usually wins, because real-world errors come more often from bias than from variance.

Any loss function works

Everything so far used squared error. Boosting works with any differentiable loss, because the "residual" is really the negative gradient of the loss: log-loss for classification, Huber for robust regression, Poisson for counts. The algorithm stays the same and only the residual formula changes. This generalization is Friedman's (1999); before it, boosting variants looked like separate methods.

Modern implementations

The basic algorithm is unchanged since 1999. The widely used libraries differ in how they make it fast and keep it from memorizing the data. XGBoost scores splits with a second-order approximation of the loss (curvature as well as slope), puts an explicit penalty on leaf values, and learns a default direction for rows with missing values. LightGBM bins each feature into a few hundred buckets so that split search works on histograms, and grows each tree leaf by leaf instead of level by level. CatBoost targets categorical features: it encodes categories using only the rows that come before each row in a random ordering, and applies the same ordering idea to boosting itself, so that no row's residual is computed by a model that was fit to that row. It also grows oblivious trees, which use the same split at every node of a level.
