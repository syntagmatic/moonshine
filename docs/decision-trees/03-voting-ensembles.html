Voting Ensembles

Chapter 3 of 6. Averaging many trees trained on resampled data cancels most of a single tree's instability, down to a floor set by how correlated the trees are. Random feature subsets lower that floor.

Chapter 2 ended with the idea of combining many trees. The reason to combine them is that trees are unstable: removing a few rows can produce a structurally different tree, however the splits are scored or α is tuned. Bagging trains many trees, each on a slightly different version of the data, and averages them so that most of the variation cancels. This chapter asks how far that averaging can go.

Bootstrap samples

Each version is a bootstrap sample: draw rows with replacement until you have the original count. Some rows appear twice and some not at all. The trees diverge only because they saw different samples, and averaging cancels the divergence.

Every bootstrap leaves out about a third of the data. Passing those rows through the trees that didn't see them gives a free validation set, the out-of-bag estimate.

Correlation between trees

If one feature is far more predictive than the others, every tree picks it for the root split. The trees end up highly correlated, and past a certain number of trees bagging stops improving.

Suppose each tree's prediction at some point has variance σ² around its mean, and any two trees have correlation ρ. The variance of the average of B trees is then

Var(average) = ρσ² + (1 − ρ) σ² / B

The second term shrinks as trees are added. The first does not depend on B at all. With ρ = 0.5, no number of trees gets the variance below half of a single tree's (Hastie, Tibshirani and Friedman, equation 15.1). Lowering the floor requires lowering ρ. Random forests do this by considering a random subset of features at every node. The dominant feature is unavailable at most nodes, so the trees diverge structurally and correlation drops. Breiman recommended √p features per split for classification and p/3 for regression.

Extra-Trees

Extra-Trees go one step further and pick a random threshold per feature instead of the best one. Each tree is worse, but the forest is more decorrelated and often beats a standard random forest on noisy problems. In an ensemble, diversity between trees can matter more than the quality of any one of them.

Tree depth in bagging

A single tree is usually pruned, but bagged trees are grown fully. Averaging removes variance and does nothing for bias, so each tree should be deep and expressive (low bias, high variance). A pruned tree carries extra bias that averaging cannot fix. Random forests in scikit-learn have no max depth by default. XGBoost uses shallow trees because its trees are added rather than averaged, which is the subject of the next chapter.

Random forests in practice

Random forests are still the first thing many data scientists try. They need little tuning and no preprocessing for mixed data types, give feature importance and out-of-bag error for free, and are competitive with careful deep learning on tabular data. The main cost is inference speed: 500 trees means 500 lookups per row.
