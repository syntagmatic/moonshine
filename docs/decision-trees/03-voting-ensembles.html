Voting Ensembles

Chapter 3 of 8. A single tree is jumpy. A hundred trees averaged are rock-steady. But the trees have to actually disagree for averaging to help, and if they don't, a second trick (hiding features at random) forces them to.

Trees are unstable: removing a few rows produces a structurally different tree. The jitter limits a single tree's usefulness regardless of how splits are chosen or α is tuned.

Bagging trains many trees, each on a slightly different version of the data, and averages them. Most of the jitter cancels.

Bootstrap samples

Each version is a bootstrap sample: draw rows with replacement, keeping the original count. Some rows appear twice, some not at all. Train a tree on the sample, repeat.

There's no clever data augmentation. The trees diverge because they saw different samples; averaging cancels the divergence.

Every bootstrap leaves out about a third of the data. Passing those rows through their respective trees gives a free validation set (the out-of-bag estimate).

The correlation ceiling

If one feature is far more predictive than the others, every tree picks it for the root split. Trees end up highly correlated and averaging buys little. Past a certain number of trees, bagging stops improving.

Random forests add one step: at every node, consider a random subset of features. The dominant feature isn't available at most nodes, the trees diverge structurally, and correlation drops.

Breiman's recommendation: √p features per split for classification, p/3 for regression.

Extra-Trees

If hiding features helps, hiding the threshold also helps: pick a random threshold per feature instead of the best. Individual Extra-Trees are worse, but the forest is more decorrelated and often outperforms a standard random forest on noisy problems.

For an ensemble, individual tree quality matters less than tree-to-tree diversity.

Bagged trees should be deep

Single trees prune aggressively. Bagged trees grow fully, with no pruning. The bias-variance logic: individual trees want low bias (deep, expressive) and high variance, since averaging kills variance. A pruned tree is higher-bias, which averaging cannot fix.

Every modern ensemble library defaults to this. Random forests in scikit-learn use no max depth. XGBoost uses shallow trees because they are added, not averaged — a different operation, covered in the next chapter.

Where forests shine

Random forests are still the first reach for many data scientists: minimal tuning, no preprocessing for mixed data types, free feature importance, free out-of-bag error, and competitive with careful deep learning on tabular data.

The main limitation is inference speed: 500 trees means 500 lookups per row. Chapter 8 covers a structural fix.

Takeaways

  • Trees are jittery, averaging cancels jitter. Bagging trains many trees on bootstrap resamples and averages predictions.
  • Bagging plateaus at the correlation floor. Trees trained on similar data end up correlated; averaging correlated predictions helps less.
  • Random forests break correlation. Hide √p features per split and trees are forced to diverge structurally.
  • Extra-Trees go even further. Randomise the split threshold too. Weaker individual trees, but more diverse forest, often better overall.
  • Don't prune bagged trees. Individual trees want to be low-bias; averaging handles variance.
  • Out-of-bag error is a free validation set. Every bootstrap leaves out about a third of the data (1/e ≈ 36.8%). Predict on those rows to estimate generalisation.
