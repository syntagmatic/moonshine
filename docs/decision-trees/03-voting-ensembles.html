Voting Ensembles

Chapter 3 of 6. Averaging trees trained on resampled data cancels most of their jitter, down to a floor set by how correlated the trees are.

Drop a few rows and a tree's splits can move. Bagging trains many trees, each on a resampled copy of the data, and averages them.

What does a bootstrap sample leave out?

Each copy is a bootstrap sample: n rows drawn with replacement from n. A given row is missed with probability (1 − 1/n)n, so every tree has roughly a third of the data it never saw.

Figure 1. Seeded simulated bootstrap draws of 30 row indices. Strip: the latest sample, one dot per time a row was drawn, with orange rings on the rows it left out. Bars: across all samples so far, the share of rows drawn 0, 1, 2, ... times; the ticks are the binomial probabilities. The figure opens with 40 draws already made.

What do random features and thresholds change?

Trees grown on overlapping samples of the same data make similar splits, so ρ sits well above zero. A random forest lowers it by letting each node consider only m of the p features. Extra-Trees (Geurts, Ernst and Wehenkel, 2006) also draw each candidate threshold at random instead of searching for the best one.

What does a lower ρ cost?

Fewer features per split lower ρ but make each tree worse. Figure 4 measures both.

Figure 4. The Figure 3 problem, measured. For each m and threshold rule, 30 seeded training sets each grow 20 fully grown trees, predicting at 100 test points. Line chart: ρ, the correlation between two trees from the same training set (solid dots: best threshold; hollow: random). Bars: expected squared error of a B-tree forest against the true curve, as bias² plus variance ρσ² + (1 − ρ)σ²/B; in each pair the left bar uses the best threshold and the right a random one. At B = 1 the ranking flips: randomness only hurts a lone tree. The textbook regression default, ⌊p/3⌋ = 1 feature here, gives the worst of the four m values; scikit-learn's forest regressor has defaulted to all features, plain bagging, since version 1.1.

How deep should bagged trees grow?

Averaging removes variance and leaves bias alone, so bagged trees are usually grown to full depth; scikit-learn's forests set no depth limit by default.

Figure 5. Squared error against the true curve by maximum depth, for a single tree on the whole training set and a forest of 30 bagged trees (m = 4), both averaged over 10 seeded simulated training sets of the Figure 3 problem. Rings mark each curve's minimum.

Depth that ruins a single tree barely moves the forest, though with noisy labels shallower trees still help a little (Hastie and colleagues, section 15.3.4). With less noise the difference all but vanishes.

Is out-of-bag error an honest test?

The rows a tree never saw are a free validation set. Predict each row with only the trees that left it out, and the error of those predictions is the out-of-bag estimate.

Figure 6. Curves: for one seeded training set of the Figure 3 problem, out-of-bag RMSE and RMSE on 500 fresh test rows as bagged trees are added. Both are measured against noisy labels, so neither can drop below the noise's standard deviation (dashed). Scatter: the two numbers at B = 100 for 40 training sets; click a dot, or focus one and use the arrow keys, to show its curves.

With few trees the out-of-bag curve runs high, since each row is predicted by only about a third of them. By a hundred trees the two agree to within the spread between training sets.
