Reading the Forest

Chapter 5 of 8. A single tree is readable. A thousand trees are not. Two tools recover the readability: one global ("what does the model care about?") and one per-prediction, "why did it say that?"

A single decision tree is interpretable: draw it, point at each split, explain it. That's gone for a thousand boosted trees, where the prediction is a sum of tiny contributions and no one tree carries the explanation.

Two techniques recover interpretability: a global view (what features the ensemble relies on) and a per-prediction view (how each feature contributed to a specific call).

What a split tells you

Before a split there's uncertainty about the label; after, knowing which side of the threshold a row fell on, usually less. The reduction is information gain. High-gain splits partition data into purer groups.

Summing information gain across nodes where a feature was used, weighted by rows passing through, is the standard mean decrease in impurity metric.

It has a famous failure mode.

The ID-column trap

A unique identifier (user ID, microsecond timestamp) splits every row into its own leaf. Every leaf is perfectly pure, gain is maximal, and the resulting tree is useless on any new row with an unseen ID — the feature has the highest possible importance and zero signal.

C4.5's fix: normalize gain by how much the split fragments the data. A balanced binary split has 1 bit of split entropy; a thousand-way split has ~10 bits. The gain ratio collapses the ID column's score to near-zero while leaving informative features alone.

Modern libraries defend against this with binning or target encoding. The takeaway: if feature importance is dominated by something that looks like a timestamp or ID, check for leakage.

Per-prediction attribution

Global importance shows what the model cares about on average. Per-prediction attribution answers why a specific prediction came out where it did: this house's predicted price was $70k above average — which features pushed it up, and which down?

Shapley (1953) gives the answer from cooperative game theory: to fairly credit each team member for a team's output, simulate every ordering in which members could have joined the team. Each member's marginal contribution is the change when they joined; their credit is the average across orderings.

For ML: features are team members, output is the prediction, baseline is the average prediction with no features known. Each feature's Shapley value is its average marginal contribution as features are revealed.

The Shapley value is the unique scheme satisfying a few fairness axioms. The catch: 2p model evaluations per prediction. For 20 features, a million; for 50, intractable.

TreeSHAP

Lundberg (2017): for tree models, Shapley values can be computed exactly in polynomial time. When a feature is "absent" from a tree, you take both children of nodes that test it, weighted by training rows down each branch — turning exponential subset averaging into a structured walk over the tree.

TreeSHAP runs in O(T · L · D²) time. On a typical forest, that's milliseconds per prediction. Values are exact and sum to the prediction minus baseline.

What SHAP doesn't tell you

SHAP describes what the model is doing, not what the world is doing. If the model learned the wrong pattern, SHAP faithfully explains the wrong thing. A large SHAP value means the model depends on the feature, not that changing the feature would change the outcome. For the causal question, see the next chapter.

Shapley handles feature interactions: if two features only matter together, SHAP credits both. This is one reason TreeSHAP has been adopted in regulated industries.

Two views

Information gain shows which features the tree learned from. SHAP shows which features explained a given prediction. The first audits model reliance; the second justifies a specific decision to a user, a regulator, or yourself.

Takeaways

  • Information gain measures split quality. But raw gain catastrophically overweights high-cardinality features like IDs.
  • Gain ratio fixes this. Normalise by the split's own entropy. A 1000-way split needs 10× the gain of a binary split to score as well.
  • Shapley values give axiomatic local attribution. Each feature is credited its average marginal contribution across all feature orderings.
  • General Shapley is exponential. 2p subsets per prediction. For real models, intractable.
  • TreeSHAP is polynomial. For tree ensembles, a clever dynamic programming over decision paths computes exact Shapley values in O(T · L · D²).
  • Attribution ≠ causation. SHAP explains the model. For intervention questions ("what would change?") you need causal trees, next chapter.
