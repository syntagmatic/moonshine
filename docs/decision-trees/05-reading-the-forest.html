Reading the Forest

Chapter 5 of 6. A single tree can be read by looking at it; a thousand cannot. Feature importance shows what the model relies on overall, and Shapley values explain a single prediction.

Chapter 4 built models from hundreds of boosted trees. A single decision tree can be drawn and each split explained. A thousand boosted trees can't: the prediction is a sum of small contributions and no one tree carries the explanation. This chapter asks what can still be read from such a model.

What a split tells you

Before a split there is some uncertainty about the label. After it, knowing which side of the threshold a row fell on, there is usually less. The reduction is information gain. Summing it over the nodes where a feature is used, weighted by the rows passing through, gives the standard mean decrease in impurity importance, which has a well-known failure mode.

ID columns

A unique identifier (user ID, microsecond timestamp) splits every row into its own leaf. Every leaf is pure and the gain is as large as it can be, yet the split is useless on any new row with an unseen ID. The feature gets the highest possible importance while carrying no signal.

C4.5 fixes this by normalizing gain by how much the split fragments the data. A balanced binary split has 1 bit of split entropy; a thousand-way split has about 10 bits. The resulting gain ratio divides the ID column's gain, which can't exceed the label's one bit, by log2 N, so its score falls from about 1 to about 0.14 at N = 120. That is a large cut but not a knockout. The penalty grows only with the logarithm of N, so the ID column still outscores weak features and can trade places with a real one.

Modern libraries defend against this with binning or target encoding. In practice, if feature importance is dominated by something that looks like a timestamp or an ID, check for leakage.

Per-prediction attribution

Global importance shows what the model relies on overall. Per-prediction attribution asks about one prediction: this house's predicted price was $70k above average, so which features pushed it up and which pushed it down?

Shapley (1953) answered the analogous question in cooperative game theory. To credit each member of a team fairly for the team's output, consider every order in which the members could have joined. A member's marginal contribution is the change in output when they joined, and their credit is its average over all orders.

In ML the features are the members, the output is the prediction, and the baseline is the prediction with no features known. A feature's Shapley value is its average marginal contribution as features are revealed. It is the unique scheme that satisfies a few fairness axioms, but it takes 2p model evaluations per prediction: about a million for 20 features, and out of reach for 50.

TreeSHAP

Lundberg, Erion and Lee (2018) showed that for tree models, Shapley values can be computed exactly in polynomial time. When a feature is "absent", the algorithm follows both children of every node that tests it, weighted by the training rows down each branch, which turns the exponential average over subsets into a walk over the tree. TreeSHAP runs in O(T · L · D²) time, milliseconds per prediction on a typical forest, and its values sum exactly to the prediction minus the baseline.

Limits of SHAP

SHAP explains the model, and if the model learned the wrong pattern, SHAP explains the wrong pattern faithfully. A large SHAP value means the model depends on the feature. It does not mean that changing the feature in the world would change the outcome.

Shapley values do handle interactions: if two features only matter together, SHAP credits both. That is one reason TreeSHAP has been adopted in regulated industries. Information gain audits what the model relies on overall, and SHAP justifies one decision to a user, a regulator, or yourself. The causal question, what would happen if a feature changed, needs a different kind of tree, which is the subject of the last chapter.
