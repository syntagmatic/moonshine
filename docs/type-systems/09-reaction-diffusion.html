§2 · Name the types

Shapes ride along in the type

Under the hood each field is a flat Float32Array of length 128 · 128 = 16384. That's a runtime fact. The type wraps it in two natural-number parameters so the compiler can track what shape the array pretends to be:

-- Natural-number parameters: w, h, k live at the type level. type Field (w :: Nat) (h :: Nat) = Array 2 Double -- refined: dim 0 = w, dim 1 = h type Stencil (k :: Nat) = Array 2 Double -- refined: k × k, k odd laplace5 :: Stencil 3 -- the 5-point star laplace9 :: Stencil 3 -- the 9-point (with corners) variant laplace5x5 :: Stencil 5 -- a wider isotropic Laplacian sobelX :: Stencil 3 -- edge detector, horizontal convolve :: Stencil k -> Field w h -> Field w h step :: ReactionParams -> Field w h -> Field w h -- built on convolve

convolve's signature promises: for any odd k and any w,h, take a k×k stencil and a w×h field and return a field of the same shape. The output shape equals the input shape at compile time, no runtime check. A [2×3] stencil is rejected before a single multiplication runs; adding a Field 128 128 to a Field 64 128 likewise.

This is "dependent-types lite". Full dependent types let the shape be any expression; shape-indexing asks only for natural-number parameters, enough to catch dimension-mismatch bugs, cheap enough for Rust, Haskell (with DataKinds), Idris, and Swift.

§3 · Signature diagram

Every pipe carries its shape

Here is step drawn out. The stencil arrives on its own tagged pipe, a [3×3]. The field arrives on a wider pipe, a [128×128]. The output field's tag is the same as the input field's tag because the signature says so. The shape tags are rendered by TV.shapeIndex; think of them as the type checker's commentary floating over each wire.

step :: ReactionParams -> Stencil 3 -> Field 128 128 -> Field 128 128 where ReactionParams = { F :: Scalar, k :: Scalar, dU :: Scalar, dV :: Scalar }
The purple brackets are the shape index. The wide teal pipes carry the field; the narrower pipe carries the 3×3 stencil. A dot animates through to show that one step consumes a stencil and a field and produces a field of the same shape — a promise visible in the diagram and enforced by the type.
§4 · What it lets you say

A stencil is a type-level value

Because the shape is part of the type, we can enumerate stencils of a given shape and treat them as different types rather than different arrays. Four stencils below, all applied to the same seeded blob. A Laplacian smears. An edge-detector emphasizes the boundary. A 5×5 wider kernel blurs farther per step. The field shape stays [64×64] throughout, that's a compile-time fact; the behavior is the thing that changes.

Every tile runs the same convolve :: Stencil k -> Field 64 64 -> Field 64 64, differing only in which Stencil k they pass. Swap a Stencil 3 for a Stencil 5, the buffer layout changes but the signature still type-checks. Swap a [2×3] shape in, and the line wouldn't compile.

The gallery is the expressiveness payoff. You can ship a library of named stencils, each with its own type, and combine them via well-typed combinators, transpose :: Stencil k -> Stencil k, compose :: Stencil k -> Stencil k -> Stencil k, knowing the dimensions will always line up.

Shape is the easy guarantee. The harder one is the symmetry group of the lattice itself. Lattice-gas automata confronted this in the 1980s: the Hardy–Pomeau–de Pazzis (HPP) model restricted fluid particles to four cardinal directions on a square grid and failed to reproduce Navier–Stokes at the continuum limit. The reason was group-theoretic: the point symmetry group of a square lattice is too small to guarantee a 4th-order isotropic tensor. Frisch, Hasslacher and Pomeau (FHP) replaced the square with a hexagonal lattice (C₆ᵥ is large enough) and the macroscopic hydrodynamics fell out. The lattice's group did the work.

HPP-style square · Stencil 3

only the four grid-axis neighbours contribute, the point group D₄ is not rich enough
The stencil's dihedral group is D₄, not SO(2). 90° is a symmetry, 60° is not. No matter how you tune F, k, or dt, the long-wavelength limit of this step function is not isotropic Navier-Stokes, it is the HPP failure mode rendered at reaction-diffusion scale.

FHP-style hex-isotropic · Stencil 3

diagonal neighbours included with weights that recover the isotropic 4th-order tensor
Same Stencil 3 type, different entries. The weights ¼ · 1 · ¼ / 1 · −3 · 1 / ¼ · 1 · ¼ stand in for the C₆ᵥ invariance that FHP achieved literally. The pattern curls and branches as the chemistry demands.
Both panels run Gray-Scott with identical parameters, identical seed, identical dt. The only difference is the Laplacian stencil — which is to say, the lattice symmetry group that the step function inherits. This is the same argument FHP made for Navier–Stokes, transplanted to Turing patterns. #12 §5d specializes this to a true 7-point hex stencil where the group action is exact, closing the loop.

The type-system move: promote the lattice's point group to a type parameter, Stencil k (PointGroup g). A diffusion written against PointGroup C₆ᵥ cannot be implemented on a Lattice D₄; the group tag catches the physics that the shape index didn't. Lattice gauge theory does the same when it discretizes SU(3) onto a hypercubic lattice.

§5 · Carry-forward

We added. TV.shapeIndex, a compact [w×h] tag that rides on a pipe the way a color does, naming a type-level number. Shape-dependence is now an axis of the visual vocabulary. The teal field palette (--c-field-lo → --c-field-hi) is a per-explainer extension that stays clear of the reserved six.
