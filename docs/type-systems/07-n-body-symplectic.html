N-Body, Symplectic

Three gravitating bodies. A phantom type tag on the integrator tells the type checker — and the eye — whether the Hamiltonian will still be conserved a thousand steps from now. Two functions with the same value signature: only one respects the geometry of phase space.

§1 · Cold sim

Three equal masses tracing each other through gravity

Three point masses, all equal, pulling on each other through inverse-square gravity. The initial positions and velocities are the classic Chenciner–Montgomery figure-eight choreography: a single closed curve that all three bodies chase, each one lagging the next by a third of the period. It is beautiful, and it is fragile — the total energy is conserved exactly by the differential equations, but the discrete integrator you pick decides whether your simulation still knows that after a hundred revolutions.

Left: positions of the three bodies, with fading trails. Right: total energy H = T + V plotted over time — the dashed line is H₀, the true energy. Switch integrator and watch what happens to the right-hand curve. Euler sheds energy like a leaking balloon; leapfrog oscillates around H₀ without drift. Switch config to Lagrange equilateral and the same drift manifests as a different physical pathology: the rigid triangle distorts, one corner flies outward, and the L4/L5 Trojan stability is gone.

§2 · Name the types

A phantom tag for what the function preserves

At the value level, all three integrators above have the same signature: take a Hamiltonian, take a state, take a timestep, return a new state. You cannot tell them apart from their input and output types alone. So we reach for a phantom type — a type parameter that appears in the signature but has no runtime representation. It exists solely to carry a claim.

data Euler -- empty; exists only as a tag data Semi data Symp newtype Integrator law = Integrator (Hamiltonian -> State -> Dt -> State) -- ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ -- the value-level signature is identical for all three euler :: Integrator Euler -- drifts: H(t) - H₀ grows secularly semi :: Integrator Semi -- better — implicit in velocity update leapfrog :: Integrator Symp -- preserves H to leading order, forever

The tag law is the guarantee. Integrator Euler and Integrator Symp have the same arrows between the same types; what distinguishes them is a claim about the function's behavior over many steps, not a local property you could spot in one evaluation. This is the headline: the type-level distinction captures a long-run invariant that no single call can witness.

In a language with phantom types you can export a safer constructor for downstream code:

-- Only accepts integrators that claim symplecticity. simulate :: Integrator Symp -> Hamiltonian -> State -> [State] simulate (Integrator step) h s0 = iterate (\s -> step h s dt) s0

A caller who tries to pass euler in gets a type error — not because Euler produces the wrong type of value, but because it makes the wrong type of promise.

§3 · Signature diagram

Same pipes in, same pipes out — different tag on top

Drawn as a signature diagram, the three integrators differ in exactly one visual element: a small superscript tag above the output pipe. The Hamiltonian and State inputs are products; the timestep is a Time pipe; the output is a new State pipe. The phantom law rides along with the arrow like a label on a shipping container — it doesn't change the cargo, it changes what you are allowed to assume about the cargo's journey.

Three panels, one per integrator. The pipes, products, and step box are identical. Only the floating tag above the output differs — Euler, Semi, Symp — and that tag is the claim the type system relays to callers.
§4 · What it lets you say

The Hamiltonian is a wall in phase space

The geometric payoff. Phase space for one body of the 3-body problem is four-dimensional (two position, two momentum), but the key picture compresses down into one plane: radial position vs. radial momentum for a single body, conditioned on the rest. The surface H = H₀ — the true initial energy — is a 1D curve in that plane, and the type Integrator Symp makes a geometric promise: the trajectory stays near this wall.

Below, two trails are overlaid. The violet one is leapfrog :: Integrator Symp; it hugs the dashed energy wall, oscillating around it by a bounded amount. The red one is euler :: Integrator Euler; it drifts steadily outward, away from the wall, because every step bleeds or gains a little energy — and the bleeding accumulates. This is the type promise rendered literally.

Phase-space projection (radial position r, radial momentum pr) of body 0. The amber dashed curve is the constant-energy level set H = H₀ — the refinement predicate that Integrator Symp claims to preserve. Leapfrog's orbit hugs it; Euler's unwinds outward, no matter how long you wait.

That the phantom tag is doing real geometric work is the lesson of the series carried through here: in #4 a refinement predicate drew the non-negativity walls of a phase portrait. Here a phantom tag on an integrator — a function type — makes a claim about the trajectory's relationship to a wall. Same visual vocabulary (TV.wall, dashed boundary), new grammar (claim is carried on the function, not the state).

The three equal-mass Chenciner–Montgomery case carries a second invariant the phantom tag doesn't yet name: permutation symmetry. Relabel body 1 as body 2, body 2 as body 3, body 3 as body 1, and the physics is unchanged — that's the group S₃ acting on the state. A well-typed step is therefore also equivariant: step ∘ permute ≡ permute ∘ step. Lagrange's equilateral triangle and its L4/L5 Trojan points sit at the fixed-point set of this action; a numerical bias that evaluates "body 1 pulls on body 2" with different floating-point rounding than "body 2 pulls on body 1" breaks the commuting diagram by one ULP per step and, a million steps later, ejects the Trojans. #12 §5a respecializes this sim to the equilateral configuration; the type the phantom tag would acquire there is exactly Integrator (Symp ∧ S₃-equivariant).

§5 · Carry-forward

We added. Phantom tags on function types. Three integrator variants (Euler, Semi, Symp) reserved in the extension palette. The idea that two functions with identical value signatures can still carry different type-level promises, and that those promises are visible in phase space as how close the trajectory stays to a conservation wall.

Reused where. #8 uses the same phantom-tag pattern for effect systems: Pure, Rand, IO tags on otherwise-identical step functions. #11's type lattice plots the phantom-tag dimension as a parcoords axis, eleven simulations side by side. #12 §5a respecializes the 3-body sim here to the Lagrange triangular equilibrium, where the three bodies sit at the corners of an equilateral triangle — the state space carries an S₃ = Weyl(A₂) symmetry that the Hamiltonian respects.
