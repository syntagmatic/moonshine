Random Walks & Effect Systems

A step function's type is not just State → State. It's State → e State, where the effect tag e records what capabilities the function needs to run, and therefore what guarantees you're allowed to expect of it.

§1 · Type first

Effects live on the arrow

An effect system adds a static description of what evaluating a function may do. Lucassen and Gifford used this idea to track side effects separately from value types.

This article uses a tiny teaching lattice: Det ⊂ Rand (Seed s) ⊂ Rand Ambient ⊂ IO. Each step still returns a state, but the arrow records which capabilities the step may use.

data Det a data Seed (s :: Nat) data Ambient data Rand seed a data IO a type Step f = State -> f State deterministic :: Step Det seededWalk :: State -> Rand (Seed 42) State unseeded :: State -> Rand Ambient State

The live figure gives the lattice a behavior. The cyan path is closed-form, so it is Det. The purple path reads a seeded generator. The magenta path reaches into ambient randomness.

Press replay: cyan retraces because time is deterministic; purple retraces because it is reseeded; magenta usually draws a different path because no seed witness was supplied.

Each trajectory carries an effect strip on its right edge. The active tag is filled; dimmer tags below are capabilities this walker does not need. Det ⊂ Rand ⊂ IO: a less-capable walker can run anywhere a more-capable one is allowed.
Det · closed-form, replayable from t=0 Rand (Seed s) · replayable from s Rand Ambient / IO · no replay promise

The tag witnesses what the function can do. Det State says the next state was computed without environmental access. Rand (Seed 42) State also names which run you get.

Subtyping follows capability. A Det function can run where a random one is allowed because it simply leaves the generator unused. A seeded random function can run where ambient randomness is allowed because it picks one run from the family.

§2 · Signature diagram

The arrow carries a color now

Two signatures stacked. Step Det :: State → Det State on top; Step (Rand s) :: State → Rand s State below. The input pipe is blue (Position, a pair of coordinates, is the State). The output pipe's effect band is colored by the effect tag: Det cyan, Rand (Seed s) purple. Capability isn't a runtime flag; it's painted onto the arrow.

The effect strip sits above the output pipe. For Rand (Seed s) the seed readout follows the live seed control in §1, showing that the arrow has chosen one specific run from the random family.
§3 · What it lets you say

The replay guarantee, visualized

Top row: two copies of the seeded walker from the same state with the same seed. Their paths coincide point-for-point: Rand (Seed 42) names one specific walk, so evaluating it twice returns the same path.

Bottom row: two copies of the unseeded walker, same state, rule, and step size. They usually diverge at once. Rand Ambient makes no promise about which run you get.

Top: Rand (Seed 42) twice, so the two paths lie on top of each other. Bottom: Rand Ambient twice, so the type gives no equality promise between runs.

In this toy lattice, every rung up widens the set of programs and weakens the guarantee. In a stochastic simulation like #4's predator-prey lattice or #6's contact graph, Rand (Seed s) turns one sampled cluster into a reproducible value. Without the seed witness, the cluster remains a random variable. #11 plots this effect height as one axis of the signature lattice.

§4 · Carry-forward

We added. TV.effectStrip as the new visual vocabulary, with capability tags stacked beside a trajectory in the effect palette (Det cyan, Rand purple, IO magenta). The seed-as-type-parameter pattern: Seed (s :: Nat) is a compile-time witness of which run you'll get, not a runtime value buried in a closure. And the reading that an effect tag is a witness of capability, a property the call site can see without looking inside the function.

Reused where. The effect strip returns in #9 when shape becomes a compile-time witness (the same "band next to the arrow" idiom for a different property) and in #10 when traits / contracts become witnesses of what a type can do. In #11 the effect rank (the height of the strip) becomes one axis of the parallel-coordinates view, so every simulation in the series is plotted partly by how much environment it needs.
