Fitness Landscapes and Genetic Algorithms

Three traits — Fitness, Mutate, Cross — form a contract. Any type that satisfies all three plugs into the same solver, be it a 2D point, a bit string, or a phrase of English.

§1 · Cold sim

A population of points climbs a fitness landscape

A 2D fitness function with four Gaussian peaks. Eighty candidate points scatter across it; each generation, the solver ranks them by fitness, keeps the best, crosses them pairwise, and perturbs the offspring. Watch the cloud converge toward the tall peak.

gen 0
Dark = low fitness, gold = high. Each white dot is a candidate; the larger gold dot is the current best. The solver is the same algorithm the gallery in §4 uses on bit strings and sentences.
§2 · Name the types

The contract is three traits

A candidate type a is evolvable when three operations are defined on it: a way to score a candidate, a way to perturb one, and a way to combine two. The step function depends on nothing else.

class Fitness a where evaluate :: a -> Double class Mutate a where mutate :: Rate -> a -> Rand a class Cross a where cross :: a -> a -> Rand a type Population a = [a] step :: (Fitness a, Mutate a, Cross a) => Rates -> Population a -> Rand (Population a)

The constraint in parentheses — (Fitness a, Mutate a, Cross a) — is the contract. It says "give me any type a that has these three operations and I can run the solver on it." The body of the step function never mentions a concrete type.

§4 · What it lets you say

One solver, three worlds

Here is the same step function running on three different candidate types. Each tile instantiates the three traits for its type; the solver is untouched.

a = Point (2D)

Fitness = -dist² to target
Mutate = + Gaussian
Cross = midpoint
—

a = BitVec 20

Fitness = # bits matching
Mutate = flip bits
Cross = 1-point splice
best: …
goal: 1010 1010 1010 1010 1010

a = String

Fitness = # chars matching
Mutate = random letter
Cross = splice at k
best: …
goal: METHINKS IT IS LIKE A WEASEL
The points tile uses Euclidean fitness and Gaussian mutation; the bit tile uses Hamming fitness and flip mutation; the string tile uses character-match and letter-swap. Same ranking logic. Same crossover fold. Same type signature.

The constraint (Fitness a, Mutate a, Cross a) => step is the type-theoretic version of a proof obligation. Each constraint is a proposition — "this type has a fitness function," "this type can mutate," "this type can cross" — and the compiler demands a witness for each before it will let step be instantiated at a. The dictionary the compiler passes in at runtime is literally the evidence the type system checked at compile time. Curry-Howard, with the solver untouched.
